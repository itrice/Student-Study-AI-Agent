## 1. 修改错题保存提示“接口不存在”

### 1.1 调查结果

- 当前源码中，前端调用、编辑会话和 PATCH 路由都存在：
  - `public/app.js` 调用 `PATCH /api/mistakes/:id`；
  - `src/server.js` 提供 `POST /api/mistakes/:id/edit-session`、`GET /api/mistakes/:id/edit` 和 `PATCH /api/mistakes/:id`。
- 使用当前源码和临时数据库启动真实 HTTP 服务后，PATCH 修改返回 `200`，字段可持久化，现有 M9 HTTP 集成测试通过。
- 调查时本机 `127.0.0.1:3000` 没有监听进程；局域网 `192.168.1.66:3000` 请求超时；本机 Docker daemon 未运行。因此无法从实际运行实例确认 image tag、容器内 commit 或反向代理配置，也不能把线上现象唯一归因到某个已部署镜像。
- 最可能的根因仍是运行实例与当前源码不一致，或中间层未转发 PATCH；但本次修复不依赖该假设，前端和后端都增加了兼容路径。

### 1.2 修复

- 后端把修改逻辑提取为共享处理器，同时提供：
  - `POST /api/mistakes/:id/update`：前端默认使用的无 PATCH 兼容路径；
  - `PATCH /api/mistakes/:id`：继续支持旧客户端和既有接口。
- 前端优先调用 POST 兼容路径；若旧后端返回 `404` 且错误为“接口不存在”，或返回 `405`，自动回退到 PATCH。
- 兜底 404 增加 `ROUTE_NOT_FOUND` 错误码，便于客户端可靠识别路由缺失。
- 更新静态资源版本，避免浏览器继续使用旧脚本。

### 1.3 实际验证

在临时数据库和真实 HTTP 服务上验证：

- `1280 × 900`：修改题目并保存，请求 `POST /api/mistakes/6/update` 返回 `200`，弹窗关闭并显示成功提示；刷新后题目仍为修改值。
- `390 × 844`：同一流程请求返回 `200`，刷新后题目仍为修改值。
- 模拟旧后端对 POST 返回“接口不存在”后，前端自动改用 `PATCH /api/mistakes/7`，请求返回 `200`，保存成功。
- 服务端集成测试还覆盖了题干、学生答案、正确答案、解析、知识点、错因和附件集合的持久化；控制台未捕获异常。

### 1.4 部署后复核

实际部署实例在调查时不可达，未能记录其 image tag 与 commit。部署后应确认：

1. 浏览器 Network 中保存请求命中 `POST /api/mistakes/:id/update` 且返回 `200`；旧后端回退时为 PATCH `200`。
2. 刷新页面后题干、答案、解析、知识点和附件仍保持修改值。
3. 新建错题、删除错题和附件裁剪无回归。
4. 若仍命中“接口不存在”，应检查静态资源与 API 是否来自不同版本，或代理是否拦截了对应方法。

## 2. 字号与可读性

- `--text-meta` 从 `12px` 提升到 `14px`，标签、时间、状态、来源、分页信息和操作辅助文字统一不小于 `14px`。
- 修正 `.breadcrumb`、`.today-chip`、`.priority-footer span`、`.session-progress span` 和移动端 `.pagination-status` 的显式小字号。
- 侧栏品牌副标题允许换行，避免 14px 后在 214px 侧栏中截断。
- 自动化测试现在要求全站字号不小于 `14px`，并单独锁定导航、分页和状态元信息。
