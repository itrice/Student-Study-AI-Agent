# 题库产品补充裁决与实施口径

> 版本：1.1
> 日期：2026-11-24
> 状态：已获产品确认，作为 01～04 的补充；与 01～04 冲突时以本文件为准，但不得降低 PRD 第 13 节发布门槛。  
> 读者：开发、QA、部署、产品验收。

## 1. 首轮实施范围

本轮按 M0 → M1 → M2 → M3 先行，M4～M10 分阶段推进；不是一次性交付全部 PRD。

## 1.1 OCR 上传交互口径

- 选择或拍摄图片后直接调用同一部署环境内的 OCR Service，不显示同意勾选或二次确认。
- 图片不发送给外部多模态模型；纯文本模型只接收 OCR 文字、坐标和置信度。
- OCR 结果是可编辑候选，不得自动覆盖手工题目文字。
- 用户仍需主动选择候选题并确认导入；此前的“候选确认后写入题库”规则不变。

首轮扫描只承诺：

- 数学六年级；
- 印刷体、单栏、单页作业或试卷；
- 1 张主图 + 最多 2 张补充图；
- 单次最多 20 道候选；
- 简单版面，不含严重折痕、大面积涂画、复杂跨栏或跨页拼接。

以下后置，不作为首轮验收门槛：

- 复杂手写体、严重透视、多栏、跨页自动拼接；
- 全学科、全年级内容；
- 主观题可靠自动判分；
- 外接来源搜索必须命中；
- 电子墨水屏多页或终端作答。

全题型的“保存、显示、手机作答”仍是本轮最终目标，但首轮先验收单选、多选、判断、单空/多空填空、图文复合题；简答、证明、作图先保证可保存、可复习、可人工复核。

现有 `/api/mistakes` 路径必须保持兼容，不得因“题库”改名破坏手机端、复习和电子墨水屏。新增题库能力可在 `/api/questions` 下提供，但旧路径至少保留一个过渡期。

## 2. 图片库与服务器 CPU 兼容性（P0）

目标服务器 CPU 是否支持 `@napi-rs/canvas` 必须先验证，不能假设可用。

- 先在目标部署环境记录 CPU 指令集与真实加载/渲染错误；不得只在开发机验证。
- 若确认是 AVX/指令集或原生二进制不兼容，替换为主流、可在目标 CPU 运行的图像库/包。
- 候选优先级：
  1. `sharp` 负责解码、EXIF 旋转、缩放、灰度/原始像素；文字渲染需另行验证 CJK 字体，不得假设 SVG 文字一定可用。
  2. 纯 JS 方案（`jimp` + `pureimage`/`opentype.js` 等）作为无原生依赖回退。
  3. Python + Pillow 侧车仅在 Node 方案无法满足时提出，且必须经产品确认，不得擅自增加第二运行时。
- 所有方案必须满足：Alpine/musl、x64、目标 CPU、内置 Noto Sans SC（OFL）、运行时不联网、输出确定、容器可构建。
- 启动时增加自检；不兼容时给出明确诊断，不得崩溃或输出空帧。
- 现有电子墨水屏接口必须回归；替换库后 48000 字节、MSB 在左、0=黑、无 gzip、ETag/304、preview 一致不得回退。
- 开发计划中“复用 `sharp`”只是候选，不是当前事实；当前实现是 `@napi-rs/canvas`，以实际验证为准。

## 3. 首版识别与质量目标

使用固定素材集验收，不用“看起来还行”代替指标。

| 项目 | 首版目标 |
|---|---|
| 七题页候选 | 7/7 全部识别；不合并、不拆分、不丢题 |
| 疑似错题提示 | 召回 ≥ 90%，准确率 ≥ 80% |
| 题型识别 | ≥ 90% |
| 学生答案提取 | ≥ 85%（印刷体 + 清晰手写） |
| 客观题标准答案 | ≥ 95% |
| 内容完整题误判为残缺 | ≤ 5% |

- 没有真实模型环境时，只能用固定模型响应做功能与状态验收，不能宣称真实识别准确率通过。
- 未达到上述目标时，不得把“识别质量”标记为通过；可把功能链路标记为通过，质量项保持“阻止”。

## 4. 来源检索口径

- 首版只使用配置内、带可核对定位信息的教材/教辅/试卷/题库资料。
- 有语料时的目标：固定正例命中率 ≥ 80%；被用户采纳的候选 100% 有可核对定位；固定反例不得编造来源。
- 没有语料时：自动来源搜索后置；本期只交付“手动填写来源 + 未找到可靠来源 + 最多 3 个候选的接口能力”，不得用模型编造书名、页码或题号。
- 外部搜索如接入，必须带可验证依据；没有依据不展示为候选。
- 未确认来源始终显示“待确认/用户填写，待核验”，不得显示成确定事实。

## 5. 普通题学习闭环

- 手动录入允许选择“答对/普通题”，不要求填写错因、诊断或提示。
- 答对题导入后：分类默认“普通题”，学习状态“未学习”，不创建到期复习计划。
- 第一次“开始学习”时创建作答记录；答对不自动变成“已掌握”。
- 普通题以后答错时，自动增加“错题”分类并进入现有诊断/复习流程；原“普通题”标签可保留，分类允许并存。
- 答案待确认但内容完整的题：能判断疑似错误则“错题/待复习”；无法判断对错则“普通题/未学习”，保留“答案待确认”标记。
- 残缺题被用户手动选中并导入：保留“内容可能不完整”标记；分类按疑似错误状态，无法判断时“普通题/未学习”。

## 6. 公式、表格、作图题的内容格式

- 文字：纯文本。
- 公式：以 LaTeX/Unicode 文本保存；电子墨水屏由服务端渲染成图；首版不要求完整可视化公式编辑器。
- 表格：以扫描图片区域保存，可附文字摘要；结构化表格编辑器后置。
- 作图题：允许学生拍照提交，保存图片，不承诺自动判分。
- 图片出现在题干、材料、选项或小问中时，必须按阅读顺序保存为内容单元，不得统一退化为题目末尾附件。
- 任何无法可靠解析的内容，保留原图区域并标记“待确认”，不得静默丢失。

## 7. 电子墨水屏行为变更

新版 PRD 的 PD-12 优先于现有“20px 后截断”的实现。

- 正文最低 20px；完整内容在 20px 仍放不下时，`eink_fit_status=unfit`。
- `GET /api/eink/queue`：排除 unfit；`count` 为可显示且到期的题数；`index` 按过滤后的队列计算。
- `GET /api/eink/page?id=<unfit>`：返回 409 JSON（例如 `code=EINK_UNFIT`），不得返回 48000 字节伪帧。
- `GET /api/eink/preview?id=<unfit>`：返回 800×480 PNG，并在画面上明确标注“不适配墨水屏单页”，用于排查。
- 可显示页面仍必须满足 48000 字节、MSB 在左、0=黑、无 gzip、ETag/304、preview 与帧逐像素一致。
- 图片损坏/空白时回退文字或返回 409，不得输出空白帧。
- 设备端必须能处理队列数量变化和非 200 响应；如固件不能处理，先升级固件再发布。
- 照片题仍按现有 788×420 单页大图规则；若图片本身不可辨认，按 unfit 处理，不得用“有图就算适配”。

## 8. 验收素材与图片质量基线

- 功能验收：使用高拟真合成七题页，覆盖单选、多选、判断、多空填空、图文复合、残缺、答案待确认；配固定模型响应。
- 真实质量验收：需要用户提供真实作业/试卷照片，至少覆盖七题页、手写批改、透视/低亮度、大片黑块、超长题；需确认隐私授权。
- 真实照片未提供时：功能验收可继续，真实识别与图片质量终验标记“阻止”，不得标记“通过”。
- 图片“明显改善”首版判定：
  - 固定样本上题干、选项、几何线、单位、公式和必要辅助线 100% 保留；
  - 大片黑块样本的黑像素比例下降 ≥ 20%；
  - 人工对照确认可读性不劣于原图；
  - 任一失败则回退原图，不得判通过。

## 9. 文档统一口径

- 学习状态统一为 5 个：未学习、待复习、练习中、需巩固、已掌握。
- “全选”语义：选中所有完整候选，并保留用户已手动选中的题（包括残缺题）；“取消全选”清空全部选择。
- “全部错题”语义：完整且疑似错误 + 用户已有手动选择；答案待确认的完整题不自动进入该范围，但可被“全选”选中。
- 回归测试数量以合并后实际结果为准，不在文档中硬编码 214。
- 题目分类与学习状态永远分开；分类变化不得重置学习记录。
- 原图不可被优化图覆盖；删除权优先于“长期保留”。

## 10. 交付顺序与门禁

1. **Phase A（现在）**：CPU/图像库兼容性验证与修复；M0 契约；M1 兼容底座；M2 扫描候选页。
2. **Phase B**：M3 批量导入；M4 客观题型与图文混排；之后按 M5～M10 推进。
3. 每个阶段独立验收；M2 视觉抽查通过后再进入 M3。
4. 开发提交 PR，不合并、不部署；QA 在隔离库和独立端口验收；产品做最终符合性检查。
5. 未解决第 3、4、8 节目标时，不得宣称对应质量项通过。
