## 文档目的

本目录集中保存题库及拍照批量导入相关的产品需求、产品设计、开发计划和 QA 验收计划。

题库不是“错题页”的简单改名，而是产品中正式题目的唯一事实来源。拍照识别只产生暂时候选，
用户明确选择并导入后，题目才进入题库。

拍照选题当前只保留“选择或拍摄图片”一个入口。图片经一次内部 OCR 后，由纯文本模型将
原始字块聚合为整题框；用户调整题框并确认分析后，未修改题框复用缓存字块，移动或低置信
题框重新 OCR。确认结果进入现有候选页，用户再次确认后才能导入题库。

现行流程详见[拍照选题最终流程](07-拍照选题最终流程.md)。旧扫描图片列表、拍照选题裁剪、
“识别题目范围”按钮和自动补充图流程均为历史实现，不再作为当前 UI 基线。

## 当前边界

- 本轮按补充裁决先做 M0～M3；写文档不等于功能完成，代码交付后另行验收。
- 题库采用独立功能模块和稳定业务接口，不立即拆成微服务。
- 正式题库只有一份数据；错题、经典题、扩展题、易错题等是多值分类。
- 题目分类与学习状态分开；用户主动录入的答对题默认“未学习”。
- 原图永久保留到用户主动删除；优化图是派生内容，不得覆盖原图。
- 电子墨水屏本轮只读、单页；无法完整显示时标记“不适配”，不静默截断。

## 文档变更规则

- 产品范围变化先修改产品设计或产品需求。
- 开发只能在开发计划中记录实现建议，不得自行改变产品硬规则。
- QA 验收以产品需求第 12、13、14 节和产品设计为准。
- 业务代码实现后，实际完成状态写入既有实施进度表，不把“已写文档”标记为“功能已完成”。
