## 1. 结论与当前门禁

本轮计划只定义如何验收，不代表功能已经通过。

提交 `a8542b1` 已实现并通过自动化自测的能力：

- 唯一“选择或拍摄图片”入口；
- 首次 OCR 返回原始字块，纯文本模型聚合整题框；
- 单题和多题整题框确认；
- 未修改题框复用缓存字块，移动或低置信题框重新 OCR；
- 确认分析后进入现有候选页；
- 全部导入成功后的上传页重置；
- 部分失败时保留候选页；
- 候选题多小问、学生答案和标准答案建议。

以下能力仍不能以当前自动化测试代替真实验收：

- 系统建议答案与用户最终答案的完整冲突审计；
- 多来源候选与人工确认；
- 统一题库分类、筛选和修订；
- 扫描原图、题目区域和优化图的完整生命周期；
- 电子墨水屏单页适配状态与队列排除。

因此现行拍照选题和后续功能项仍保持“未执行”验收状态。现有 `244/244`（2026-11-26 dev 基线；
本计划初稿时为 `241/241`）自动化测试只证明实现自测通过，不能替代真实照片、浏览器、故障注入和墨水屏验收。

现有电子墨水屏渲染器在字号降到 20px 后仍会因为超长内容追加省略号。该行为不能满足新版 PRD “禁止静默省略题目内容”的硬规则；新实现交付前，不得引用旧接口报告判定本轮通过。

## 2. 验收原则

### 2.1 不可放宽的发布阻断项

以下任一项失败，QA 直接判定“不可进入部署”，不进入协商放宽流程：

| 编号 | 阻断项 |
|---|---|
| G-01 | 完成识别后、用户确认导入前，正式题库发生变化 |
| G-02 | “全选”或“全部错题”自动选中残缺题 |
| G-03 | 未选中的题目进入正式题库 |
| G-04 | 用户确认的标准答案被系统建议静默覆盖 |
| G-05 | 无可验证来源时生成书名、页码或题号 |
| G-06 | 优化图覆盖、替换或导致原图丢失 |
| G-07 | “错题库”和“普通题库”形成两份可分别修改的数据 |
| G-08 | 电子墨水屏静默截断内容后仍显示为适配成功 |
| G-09 | 关键图片在墨水屏不可辨认，且没有原图选择或回退 |
| G-10 | 多题 `discovered` 边界候选未经二次分析即可导入正式题库 |
| G-11 | 多题首轮被描述或展示为已完成小问、答案分析 |

### 2.2 判定要求

- 必须使用真实用户流程，不仅检查页面元素或接口是否存在。
- 每个场景同时记录操作前、网络请求中、成功页和重新进入后的数据状态。
- “未执行”“被阻塞”不得写成“通过”；视觉问题必须附截图和原图。
- 自动化接口测试只能作为证据之一，不能替代手机和桌面浏览器验收。
- 质量类结论必须使用固定素材和验收基线，避免同一位 QA 主观前后不一致。
- 发现缺陷时记录需求编号、复现步骤、期望、实际、严重级别和证据文件。

## 3. 测试环境与数据

### 3.1 隔离环境

- 独立分支和独立提交，不连接正式实例。
- 临时 SQLite 数据库、临时附件目录、独立端口。
- 使用 WSL Docker 镜像测试和本机浏览器测试各执行一轮。
- 桌面视口至少覆盖 1440、1152、960；手机和平板覆盖 390×844、834×1194。
- 电子墨水屏使用 800×480 PNG 预览和 48000 字节设备帧交叉验证。

### 3.2 核心七题素材

需要一张可人工核对的真实或高拟真作业页，包含以下七道候选：

| 候选题 | 内容特征 | 期望 |
|---|---|---|
| 1 | 完整单选题，答案正确 | 普通样式，可单独选择 |
| 2 | 完整选择题，带选项图片，疑似错误 | 红线提示，进入“全部错题” |
| 3 | 完整判断题，疑似错误 | 红线提示，进入“全部错题” |
| 4 | 完整图文复合题，含不同题型小问 | 一个扫描编号，内部小问有序 |
| 5 | 完整多空填空题，部分答案无法判断 | 显示“答案待确认”，不进入默认错题范围 |
| 6 | 题干预览末超出页面，残缺 | 默认不选，快捷选择永不选中 |
| 7 | 关键图形被遮挡导致残缺 | 默认不选，快捷选择永不选中 |

### 3.3 补充题型素材

七题页之外，补充覆盖：

- 单选题、多选题、判断题；
- 单空和多空填空题；
- 计算题、简答题、证明题、作图题；
- 材料题、阅读理解题和复合题；
- 题干图片、选项图片、表格、几何图和辅助线；
- 不同小问使用不同题型；
- 无法确定题型时进入“通用题”。

### 3.4 图片与失败注入素材

- 带 EXIF 方向的手机照片；
- 透视倾斜、桌面阴影和低亮度照片；
- 含有学生手写答案、红叉、红勾和无关涂画的照片；
- 含有必须保留的几何线、单位、公式和符号的图片；
- 局部黑块、反光和边缘裁切图片；
- 原图缺失、优化图损坏、优化结果为空白图的注入场景；
- 模型超时、模型拒绝、无可靠来源、来源返回超过 3 条；
- 批量导入第 N 题失败、网络重复提交、服务重启；
- 备份恢复和删除后的图片一致性场景。

## 5. 执行顺序

1. **契约审查**：开发提交第 11 节要求的实施说明、API、状态机、迁移和失败恢复说明。
2. **确定性测试**：候选状态、选择集合、幂等、答案冲突、来源上限、统一实体、图片生命周期和墨水屏适配判定。
3. **真实浏览器闭环**：唯一选图入口 → 一次 OCR 聚合整题框 → 单题/多题确认 → 缓存复用或重做 OCR → 候选页核对 → 确认导入 → 页面重置。
4. **图片质量验收**：固定素材逐张对比原图、优化图和墨水屏预览。
5. **异常与持久化**：部分失败、重复点击、重启、删除、备份恢复。
6. **容器验收**：WSL Docker 从零构建，在 Alpine 内运行测试，并通过浏览器访问容器。
7. **产品终验**：QA 汇总全部证据后提交产品；产品确认前不标记完成。

## 7. 开发交付时必须提供

- 可运行的扫描导入和统一题库实现及提交号；
- 数据库迁移、旧错题兼容和回滚说明；
- API 契约、错误码和幂等规则；
- 扫描模型、题库来源检索和答案生成的测试环境说明；
- 七题测试页、全题型测试素材和预期识别结果；
- 图片优化前后固定样例及失败样例；
- 电子墨水屏不适配判定规则、队列排除方式和测试入口；
- 批量导入部分失败的可重复故障注入入口；
- B-01～B-05 所需真实素材、标注集、准确率目标、图片基线和具体资源上限；
- 测试报告，包含通过数、失败数、已知限制和未覆盖项。

## 8. 退出标准

只有同时满足以下条件，QA 才提交产品最终验收：

- 第 13 节九项发布门槛全部通过；
- 第 4 节所有用例为“通过”，或经产品书面确认移出当前版本范围；
- 第 6 节 B-01～B-05 已形成可复现的素材、指标或资源上限基线；
- 桌面、手机、平板和电子墨水屏均有真实运行证据；
- 本机与 WSL Docker 环境均通过；
- 没有未关闭的阻断缺陷；
- 产品验收负责人明确签字或书面确认。
