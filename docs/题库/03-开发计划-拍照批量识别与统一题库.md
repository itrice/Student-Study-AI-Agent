# 拍照批量识别与统一题库开发计划

> 对应需求：[拍照批量识别与统一题库产品需求](01-产品需求-拍照批量识别与统一题库.md) v1.3
> 对应裁决：PRD 第 14 节 PD-01～PD-15
> 文档状态：产品裁决已纳入，等待终审输入；未开工
> 日期：2026-11-25
> 约束：本文不改变 PRD 的硬规则；仍需产品确认后才能进入开发

## 1. 结论摘要

当前系统已经具备单题录入、多小问、图片附件与人工裁剪、可选图片文字转录、
答案判题、掌握状态、复习计划、搜索和电子墨水屏只读页面。距离新 PRD 的主要差距是：

- 没有“扫描任务 → 多候选题 → 用户选择 → 批量导入”的独立流程；
- 题目仍以整段文字和小问题干为主，没有按顺序保存文字、公式、选项、图片和小问；
- 没有题型、统一分类/标签、标准答案建议与最终答案分离、答案冲突记录；
- 没有最多 3 个题目来源候选及人工确认；
- 没有扫描原图、题目区域、优化图和原图的完整关联模型；
- 现有电子墨水屏在文字过长时会截断，而且不会把“不适配单页”的题从队列排除；
- 现有“错题库”实际是唯一题目表，但产品界面和领域语义还没有升级为统一题库。

本轮采用**模块化单体**，不把题库立即拆成微服务。先完成扫描候选与现有题目表之间的
安全衔接，再逐阶段补齐结构化内容、答案、来源、图片优化、统一题库和墨水屏适配。

PRD 第 14 节已经冻结本轮业务口径。当前没有剩余的业务规则争议；尚未就绪的仅是验收素材、
可检索来源资料和真实模型测试环境。未提供这些输入时，可以不阻塞契约设计，但不能对真实
识别质量、来源命中和图片优化效果作通过结论。

首个可交付闭环应为：

```text
拍摄一张印刷体作业页
  → 生成多道候选题，不写正式题库
  → 候选项默认不选
  → 用户选择若干完整题
  → 一次导入到现有统一题目表
  → 失败候选可重试且不重复创建
```

该切片暂不包含自动标准答案、自动来源、复杂手写去除和全部题型，以避免首轮同时引入过多
不确定性。

## 2. 当前系统基线与差距

### 2.1 可以直接复用的能力

| 现有能力 | 可复用方式 |
|---|---|
| `mistakes` 题目主表 | 继续作为唯一正式题目实体；产品语义改称“题目”或“统一题库记录” |
| `mistake_parts` 小问模型 | 保留并扩展题型、选项和作答方式，不新建第二套题目 |
| `accepted_answers` 答案变体 | 继续用于最终答案和可接受答案 |
| 判题领域逻辑 | 复用数字、分数、百分数、比、文本等价判断，并扩展多选/判断 |
| `attachments` 与 `attachment_crops` | 继续保留原图和人工裁剪；新增扫描原图、题目区域和优化图关联 |
| 学习状态、作答、提示、复习计划 | 继续以现有题目 ID 为稳定关联键，不重建学习记录 |
| 修订历史 `mistake_edits` | 扩展记录题型、内容单元、答案建议、来源和分类的变化 |
| 图片管线 | 当前实现为 `@napi-rs/canvas`；上线前必须验证目标服务器 CPU，必要时替换为主流、CPU 兼容的图像库。候选见补充裁决第 2 节 |
| 电子墨水屏接口与缓存 | 保留 48000 字节帧、ETag/304、预览和照片回退，只升级内容来源与适配门控 |

### 2.2 当前主要缺口

| 需求 | 当前状态 | 实施缺口 |
|---|---|---|
| 多题扫描 | 单附件文字转录 | 需要扫描任务、候选题、区域坐标和独立候选状态 |
| 候选选择 | 无 | 需要默认不选、全选、全部错题、残缺默认排除和手动例外 |
| 题型 | 仅小问答案类型 | 需要题目级题型、选项、多空/复合题和小问级题型 |
| 图文混排 | 整段题干 + 附件列表 | 需要按顺序保存文字、公式、图片、表格、选项和小问 |
| 标准答案建议 | 当前“正确答案”直接作为正式字段 | 需要系统建议、用户最终答案、冲突标记和审计记录 |
| 来源 | 仅知识库解释来源 | 需要题目来源候选、定位信息、匹配度和人工确认状态 |
| 统一分类 | 当前主要是学习状态筛选 | 需要分类、标签、来源、完整度与学习状态并行筛选 |
| 图片优化 | 人工裁剪与墨水屏临时处理 | 需要扫描区域、优化派生图、质量门禁和原图恢复 |
| 批量导入 | 单题保存和单次工具幂等 | 需要按候选逐项提交、部分失败、可重试且不重复 |
| 墨水屏单页 | 会降字号，最低 20px 后截断 | 需要完整排版预检，失败时标记不适配并排除队列 |

## 3. 建议拆分的开发阶段

### M0：开发契约与迁移设计门禁

目标：冻结扫描候选、统一题目、内容单元、答案建议、来源和图片派生的最小契约。

交付：

- 数据迁移与兼容说明；
- API/领域对象契约；
- 扫描候选状态机；
- 文字、公式、图片、选项、小问的顺序模型；
- 答案冲突与来源确认规则；
- 墨水屏“可适配/不适配”的确定性判定规则。

独立验收：现有 23 道题、附件、作答、掌握证据和电子墨水屏接口的数据读取不发生变化。

该阶段是技术门禁，不单独作为产品发布切片。

### M1：统一题库兼容底座

目标：在不复制题目、不重建学习数据的前提下，把现有 `mistakes` 表升级为唯一题库主实体。

最小交付：

- 题目记录增加题型、内容完整度、来源状态、答案复核状态和墨水屏适配状态；
- 增加分类、标签、内容单元、选项、题目来源和图片派生关系；
- 现有题目自动归入“错题”，现有 `correct_answer` 视为用户已确认的最终答案；
- 现有整段题干自动回填为一个文字内容单元，小问继续使用原 `mistake_parts`；
- 现有学习状态、作答和复习计划完全保留。

独立验收：

- 升级前后题目、附件、作答、掌握证据和复习队列数量及关联一致；
- 旧接口继续可读，现有页面无回归；
- 不存在第二张正式题目表或复制出来的“普通题库”。

### M2：扫描候选最小闭环

目标：完成“模式选择 → 一页多题边界定位和编号 → 用户勾选 → 逐题分析 → 候选页”，此时仍不正式入库。

建议首轮只覆盖：

- 印刷体文字题；
- 明确的题号和题干边界；
- 普通单选、填空和计算题；
- 不含复杂表格、跨栏、严重折痕或大面积手写的页面。

交付：

- 扫描任务、完整原图、候选题区域和临时编号；
- 每道候选的完整度、疑似错误、答案待确认和识别失败状态；
- 默认不选、全选、全部错题、取消全选；
- 默认单题模式；多题首轮只定位题目边界、可见题号和区域，`parts[]` 为空；
- 用户勾选后调用 `POST /api/questions/scans/{id}/analyze` 逐题裁剪并二次分析；
- 部分题目分析失败只影响该项，成功项保留为 `analyzed`，失败项可从 `discovered` 重新分析；
- 残缺题快捷排除和手动选择警告；
- 快捷选择只修改规则范围内候选，手动选中项保留；“取消全选”清空全部选择；
- 选中状态在离开后重新进入时保留，直到扫描任务失效；
- 候选题单题放大、编辑、重新框选和排除；
- 单题和完成二次分析的候选展示动态数量的小问、学生答案和标准答案建议；
- 本阶段只保存扫描候选，不点击“导入”就不创建正式题目。

独立验收：

- 一张含 7 道完整题的示例页生成 1～7 号候选；
- 初始选择数为 0；
- 残缺题不被任何快捷选择选中；
- 手动选中残缺题后，再点击“全选/全部错题”仍保留该题；
- 题目完整但答案待确认的题可由“全选”选中；
- 未点击导入时，正式题库数量不变。
- 多题首轮不出现小问或答案分析结果。
- 勾选 2 道题二次分析时，只分析这 2 道；其他候选仍为 `discovered`。
- 第 2 道分析失败时，第 1 道保留 `analyzed`，第 2 道保留错误并可重试。
- `discovered` 候选不能导入；完成分析后才进入用户确认和导入范围。

### M3：选择后的批量导入

目标：把用户确认的候选逐题导入统一题库，支持部分失败与安全重试。

交付：

- 只导入 `analysisStage=analyzed` 且用户已确认的候选；
- 每道候选独立事务和幂等键；
- 成功、失败、重复跳过分别返回；
- 成功候选不因重试重复创建；
- 原图、题目区域和现有文字/小问进入正式题目；
- 导入后显示成功数量和失败数量；已成功题保留，失败项只重试自身。

独立验收：

- 选择 3 道题只新增 3 条记录；
- 重复点击不会重复创建；
- 第 2 道失败时，第 1、3 道可成功，失败项保留并能只重试失败项；
- 导入前取消的题不会进入题库。

### M4：结构化题目内容、题型和客观题判题

目标：摆脱“只有整段文字”的模型，支持 PRD 中的全题型录入和展示。

最小内容契约：

- 有序内容单元：文字、公式、图片、表格、选项、小问；
- 每个图片单元可引用扫描原图区域或派生题目图片；
- 题型：单选、多选、判断、填空、计算、简答、证明、作图、材料/复合、通用；
- 复合题使用一个正式题目，小问各自拥有题型和答案；
- 客观题支持单选、多选、判断、单空和多空自动判题；
- 主观题允许保存并进入复习，但明确显示“需人工/后续复核”。

建议先验收：

- 单选；
- 多选；
- 判断；
- 单空/多空填空；
- 图文混排的复合题。

独立验收：

- 选项顺序和选项图片保持在原位置；
- 修改题型后手机作答控件同步变化；
- 多空答案逐空判题；
- 主观题不因无法自动判分而无法保存。

### M5：答案建议、最终答案与冲突审计

目标：把系统建议与用户最终答案严格分离，不静默覆盖。

建议数据语义：

- `student_answer`：照片或用户录入的学生原答案；
- `suggested_answer`：系统建议标准答案；
- `correct_answer`：用户最终确认的标准答案，继续作为现有判题字段；
- `answer_review_status`：待确认、已确认、待补充、建议冲突；
- 答案确认和冲突记录写入独立审计表。

复用现有等价判断处理 `1/2`、`0.5`、`50%`、比值和单位等价；多选使用集合比较。
所有已选题都可以请求建议答案；疑似错题优先自动生成，答对题的建议不阻止导入。
系统无法可靠判断两个答案是否等价时，按冲突处理并要求用户确认。

独立验收：

- 系统建议与用户答案不等价时必须二次确认；
- 等价表示不弹冲突；
- 用户保留自己的答案后，正式题目和审计记录均显示“待复核/有冲突”；
- 无法生成答案时可留空导入；
- 用户改回等价答案或明确确认保留自己的答案后，可以解除待复核状态；
- 每次解除和再次冲突都保留审计记录；
- 安全复习接口在作答前仍不返回标准答案。

### M6：题目来源候选与人工确认

目标：最多展示 3 个可核对来源，找不到就明确留空。

交付：

- 来源候选：来源类型、名称、教材/教辅/试卷信息、章节/页码/题号、匹配度；
- 首版只展示配置内可检索、带可核对定位信息的资料；
- 用户选择、修改或“暂不确认”；
- 用户手填来源允许保存，但未验证时显示“用户填写，待核验”；
- 正式题目只把用户确认项标记为“已确认来源”；
- 未确认候选与正式来源分开保存；
- 复合题默认使用题目级来源，不自动为每个小问拼造不同出处。

独立验收：

- 达到最多 3 个候选上限；
- 无可靠来源时显示空状态；
- 用户不确认时，不会在详情页显示成确定事实；
- 低匹配候选明确标记“来源不确定”。

### M7：扫描原图、题目区域和优化图

目标：完整保留原图，并生成可回退的题目阅读版本。

建议资产关系：

- 扫描任务保存一张不可覆盖的完整原图；
- 每次扫描使用 1 张主图，并允许最多 2 张补充图；合计最多 3 张。
  该上限用于兼顾页边缺失补充、单次模型成本和服务端内存，更多图片应重新扫描或拆分任务；
- 每道候选保存原图区域坐标；
- 导入时生成题目区域图和“优化图”派生文件；
- 原图、人工裁剪、自动区域和优化图分别有独立版本与哈希；
- 删除题目时同步清理其派生文件，但共享扫描原图只在最后一个引用移除后清理。
- 未导入任何候选的扫描原图、补充图和暂存候选保留 24 小时后自动清理。

首轮优化建议：

- EXIF 方向；
- 透视/页面边界的基础校正；
- 桌面与页边阴影裁剪；
- 对比度和局部二值化；
- 学生答案、批改痕迹和无关涂画采用保守去除；清晰可分离时才生成“去作答痕迹”派生图。

手写/批改痕迹去除只能影响受控派生版本。无法可靠判断时保留原内容，题目自带几何线、
标签、单位和必要辅助线不得删除。

独立验收：

- 原图始终可访问；
- 用户能切换原图和优化图；
- 优化图缺失或质量不达标时自动回退原图；
- 无法可靠去除手写或辅助线时保留原内容；
- 原图不会被优化流程覆盖；
- 未导入扫描任务满 24 小时后清理，已导入题目的共享原图保留；
- 删除、备份和恢复包含全部派生资产。

### M8：统一题库页面、筛选与修订

目标：让错题、普通题、经典题、扩展题等只在分类和标签上不同，不生成副本。

交付：

- 唯一题库列表；
- 分类、学科知识点、题型、学习状态、来源、完整度、答案待复核和扫描批次筛选；
- 分类为多值标签；默认“命中任意所选分类”，同时提供“同时包含多个分类”筛选；
- 原图/优化图切换；
- 题目、答案、题型、分类和来源编辑；
- 修订历史；
- 跨扫描相似题提示，但不自动合并。

独立验收：

- 同一题同时拥有“错题”和“易错题”标签时仍只有一条记录；
- 答对题手动入库后默认“未学习”且不自动“已掌握”；
- 导入疑似错题默认“错题/待复习”，答对题默认“普通题/未学习”；
- 未学习、待复习、练习中、需巩固、已掌握可分别筛选；
- 跨扫描相似题只提示，用户决定新建、查看已有或取消。

### M9：电子墨水屏单页适配门控

目标：从统一题库读取结构化内容，在单页内完整排版；无法完整显示时明确不适配。

建议实现顺位：

1. 纯结构化文字和选项；
2. 清晰题目图片；
3. 结构化文字 + 必要图片的混排；
4. 优化图优先与质量回退。

适配规则：

- 先在服务端计算完整布局，不先截断再判断“成功”；
- 沿用正文最低 20px；完整内容在 20px 及以上仍放不下时，
  `eink_fit_status=unfit`；
- 不适配题不进入墨水屏队列，但手机端仍可完整查看；
- 题目页继续不显示答案、解析或用户确认答案；
- 只读，不增加终端作答。

独立验收：

- 超长题明确标记“不适配墨水屏单页”；
- 不出现半个字、重叠、越界或静默省略；
- 不适配题不进入 `/api/eink/queue`；
- 预览与设备帧仍逐像素一致、48000 字节和 ETag/304 行为不变。

### M10：端到端验收、异常和发布门禁

覆盖：

- 7 题扫描选择、批量导入、部分失败；
- 残缺题、模型不可用、来源为空和答案冲突；
- 多题型、图文混排和复合题；
- 原图/优化图切换与恢复；
- 统一题库筛选与修订；
- 墨水屏适配上榜/排除；
- 备份恢复、删除和全量学习数据清理；
- 现有回归测试（以合并后实际数量为准）。

发布门禁直接采用 PRD 第 13 节，不增加隐性放宽条件。

## 4. 题库独立模块边界与微服务判断

### 4.1 已确认的模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| 题库模块 | 正式题目、内容单元、题型/选项、最终答案、分类标签、已确认来源、修订、图片资产关联、统一查询 | 扫描临时状态、模型调度、复习策略 |
| 扫描导入模块 | 扫描任务、候选题、识别建议、临时编号、用户选择、批量导入编排 | 维护第二份正式题目或独立学习状态 |
| 学习模块 | 作答、提示、掌握证据、复习计划、统计 | 修改扫描候选或正式题目内容 |
| 电子墨水屏模块 | 布局适配、设备帧、PNG 预览、队列过滤 | 保存第二份题目或学习状态 |

扫描导入只能通过题库模块的受控接口创建正式题目。复习和墨水屏只通过题目 ID 读取题库，
不得复制正文作为各自事实来源。

### 4.2 已确认本轮不拆微服务

采用模块化单体的理由是：

- 当前产品是单学生、家庭局域网、本地 SQLite 部署；
- SQLite 是单写者模型，拆服务会引入分布式事务、幂等和备份一致性问题；
- 扫描候选、题目导入、附件文件和原图区域需要在同一业务边界内保持一致；
- 复习、搜索和墨水屏已经有稳定的题目 ID 关联，拆服务不会带来当前用户价值；
- 家庭部署不应额外要求用户维护消息队列、独立数据库和多个容器。

因此采用“一份数据库 + 清晰模块接口 + 可独立测试的领域服务”。

如果未来出现真实多设备同步、多用户并发或题库规模显著扩大，优先把**无状态视觉识别/来源搜索**
抽成工作进程或独立适配服务，而不是先拆题库数据服务。

### 4.3 物理表处理

不创建新的正式 `questions` 表，也不把 `mistakes` 改名。

- `mistakes` 继续作为物理主表，避免大规模外键迁移；
- 代码领域对象和产品文案统一使用“题目/统一题库”；
- 新增分类、内容单元、来源、答案建议和图片关系表，均以现有题目 ID 关联；
- “错题”变为分类标签或默认分类，不再代表独立数据集合。

这满足产品只有一份正式题目事实，同时降低升级风险。

## 5. 现有数据兼容升级方案

建议从 schema v13 增量创建 v14 及后续迁移，只新增、不回写学习证据。

### 5.1 题目主体

- 现有每一条 `mistakes` 都是统一题库中的一条题目；
- 默认分类为“错题”；
- 现有题目题型号新增值默认为“通用题”；
- 现有内容完整度默认为“已确认/遗留录入”，不伪造扫描信息；
- 现有 `correct_answer` 视为用户已确认答案；
- 现有 `analysis`、`hint`、诊断和知识来源继续保留。

### 5.2 内容单元回填

- 将现有 `mistakes.question` 回填为一个有序文字内容单元；
- 若题干为空但存在附件，回填图片引用单元；
- 现有 `mistake_parts` 保留，作为小问事实和判题实体；
- 为新结构化内容增加内容单元表，不删除旧题干和小问字段；
- 双读期接口可以从新内容单元生成展示，也可回退旧字段。

### 5.3 图片

- 现有原图保持不可变；
- 现有 `attachment_crops` 转为“人工裁剪派生图”；
- 新扫描原图、题目区域、优化图使用独立派生类型；
- 旧附件继续绑定现有题目，行为不变；
- 同一扫描原图可被多个候选题引用，因此不能继续只依赖单一 `mistake_id` 归属。

### 5.4 学习状态和复习

- 不重建任何作答、提示、掌握证据或复习计划；
- 现有 `new`、`practicing`、`mastered`、`relearning` 的内部值继续合法；
- 产品文案分别为“待复习、练习中、已掌握、需巩固”；
- 新增内部状态 `unlearned`，产品文案为“未学习”；
- 用户主动选择的正确题导入为“普通题/未学习”，不创建到期复习计划；
- 学生第一次开始学习后进入现有复习流程；
- 导入疑似错题继续使用现有 `new`，产品文案为“待复习”，立即进入现有复习计划。

### 5.5 修订与删除

- 新字段变化继续使用题目修订号；
- 题型、内容、最终答案和已确认来源变化写入审计；
- 删除题目时先计算共享资产引用，再删除独占派生资产；
- 全量学习数据删除同时覆盖扫描任务、候选、暂存图片和正式题目。

### 5.6 迁移验收

- 旧库升级前自动备份；
- 新迁移事务失败完整回滚；
- 重复执行幂等；
- schema v13 到 v14 的旧库升级测试；
- 23 道题、附件、作答、掌握和复习数据迁移前后计数一致；
- 旧 API 和电子墨水屏接口回归通过。

## 6. 高风险实现点与建议控制

| 风险 | 影响 | 建议控制 |
|---|---|---|
| 多题边界识别错误 | 两题合并或一题拆成多条 | 候选必须可人工重新框选；低置信度默认不选 |
| 多题首轮被误当成已完成分析 | 空白小问或伪造答案进入候选页 | 首轮固定 `analysisStage=discovered` 且 `parts[]` 为空；只允许用户勾选后二次分析 |
| 多题二次分析部分失败 | 整批失败或成功项被回滚 | 逐题调用单题流程，成功项独立保留，失败项保留边界和重试入口 |
| 学生手写与印刷内容混杂 | 学生答案、题干和批改痕迹串位 | 分开保存学生原答案和题干；无法区分时保留原图并标记待确认 |
| 自动标准答案错误 | 错答案进入后续复习 | 建议与最终答案分离；等价判断；冲突二次确认和审计 |
| 来源搜索幻觉 | 虚构书名页码 | 只显示可追溯候选；无结果明确为空；用户确认后才成为事实 |
| 题干图片位置丢失 | 选项图、几何图无法还原题意 | 使用有序内容单元和区域坐标，不把图片统一堆到附件末尾 |
| 图片优化伤及几何线 | 题意被改变 | 优化只生成派生图；提供原图对比；质量不达标强制回退 |
| 手写擦除误删题目线条 | 图形题失真 | 首轮不默认擦除；按题确认或保守保留 |
| 批量导入部分成功 | 重复题或假“全部成功” | 候选级幂等、独立事务、逐项结果和仅失败重试 |
| 相似题误合并 | 用户题目丢失 | 只提示，不自动合并；用户选择新建/查看/取消 |
| SQLite 扫描并发写 | 导入卡顿或锁冲突 | 单进程写入队列；候选按项短事务；大图处理不占写事务 |
| 扫描原图被重复清理 | 多题共享原图丢失 | 资产引用计数或共享关系表，最后引用删除时清理 |
| 墨水屏静默截断 | 题意不完整但显示成功 | 完整布局预检；unfit 不入队；手机端保留全文 |
| 题型扩展破坏判题 | 旧题无法作答 | 旧 `answer_type/comparison_rule` 保持；新题型适配层回退旧规则 |
| 内部 OCR 不可用 | 扫描流程中断 | 原图和手动框选可用；允许手填；不创建空题 |

## 7. 产品裁决落实与终审输入

### 7.1 已由 PRD 第 14 节冻结的口径

| 裁决 | 本实施说明的落实 |
|---|---|
| PD-01 | 采用独立题库模块和模块化单体，不立即拆微服务；只有一份正式题目事实 |
| PD-02 | 疑似错题导入为“错题/待复习”；答对题导入为“普通题/未学习”，不创建到期计划；其他分类由用户标注 |
| PD-03 | 快捷选择只修改规则范围，手动选中项保留；“取消全选”清空全部；选择状态保留到扫描任务失效 |
| PD-04 | 题干、关键选项或关键图形不可确认时按残缺/严重不确定处理；仅答案待确认的完整题可由“全选”选中 |
| PD-05 | 所有已选题都可请求建议答案；错题优先，答对题建议不阻止导入；主观题不可生成时明确暂不可用 |
| PD-06 | 复用可接受答案等价规则；无法可靠判断等价时按冲突处理；解除和再次冲突均写审计 |
| PD-07 | 首版只使用配置内、带定位依据的来源；复合题一个主来源；用户手填来源显示“用户填写，待核验” |
| PD-08 | 分类为多值标签，默认“命中任一”，另提供“同时包含”筛选 |
| PD-09 | 批量逐候选项导入，允许部分成功；成功项保留，失败项单独重试且不重复 |
| PD-10 | 未导入扫描原图与暂存候选保留 24 小时；已导入原图长期保留；共享原图最后引用删除后清理 |
| PD-11 | 方向、透视、裁边、去阴影、对比度和清晰化优先；作答痕迹保守去除，必要时保留并回退原图 |
| PD-12 | 正文最低 20px；20px 仍放不下即“不适配墨水屏单页”，不入队，手机端完整显示 |
| PD-13 | 单次扫描最多 20 道候选；主图沿用现有上限；补充图采用 1 主图 + 最多 2 补充图的开发上限 |
| PD-14 | 上传图片后直接调用内部 OCR，不要求二次确认；图片不发送外部多模态模型；纯文本模型只接收 OCR 文字；服务不可用仍可手动框选和录入 |
| PD-15 | 默认单题；多题首轮只定位边界，用户勾选后逐题分析；`discovered` 不生成小问/答案且不能导入，二次分析允许部分成功 |

### 7.2 仅剩的终审输入

以下事项不再涉及业务规则选择，只涉及素材、环境或主动扩大范围：

1. **固定验收素材包**
   需要提供或确认一张七题作业页、全题型样例、带学生手写/批改痕迹样例、透视倾斜样例、
   大片黑块样例和超长不适配墨水屏样例，并附人工标注的标准候选、学生答案、标准答案、
   来源和可读性预期。没有素材包可以开发，但不能完成真实识别与图片质量终验。

2. **可检索来源资料**
   需要配置首版允许检索的教材、教辅或项目资料，并提供至少若干“题目 → 可核对章节/页码/题号”
   的正例和“无可靠来源”的反例。资料未配置时，来源功能只能验收空状态和人工填写路径。

3. **真实模型测试环境**
   需要确认用于整页视觉识别、答案建议和来源检索的模型、调用额度和测试环境。
   未提供真实环境时，自动化测试可使用固定模型响应，但不得宣称真实识别准确率通过。

4. **相似题提示基线**
   跨扫描相似题只提示、不合并。需要素材包给出“应提示”和“不应提示”的样例，
   用于校准开发建议的高阈值；若产品要求扩大提示覆盖，属于质量范围变更，需终审。

5. **图片“明显改善”的固定证据**
   需要确认用于人工对比的原始照片和期望保留的线条、单位、符号、辅助线。
   开发会记录黑像素比例及处理前后预览，但最终“明显改善”以固定素材的人工对照为准。

6. **主动扩大范围的变更**
   以下均不属于本轮基线；若产品要求纳入，需要修改范围后重新排期：
   - 单次扫描补充图超过 1 主图 + 2 补充图；
   - 单次候选题超过 20 道；
   - 墨水屏多页或终端作答；
   - 外部来源搜索必须作为发布必需能力；
   - 全题型自动可靠判分或主观题自动标准答案。

## 8. 不改变的硬规则

本轮实施不得改变以下 PRD 规则：

- 识别后不能自动写正式题库；
- 候选题默认不选；
- 残缺题不能被快捷选择自动选中；
- 用户未选择的题不能导入；
- 系统建议不能静默覆盖用户最终答案；
- 没找到可靠来源时不能编造；
- 原图不能被优化图覆盖；
- 不能出现错题库和普通题库两份正式数据；
- 电子墨水屏不能静默截断后仍显示适配成功；
- 电子墨水屏本轮只读且只做单页。
