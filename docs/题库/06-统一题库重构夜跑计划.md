# 统一题库重构夜跑计划

> 版本：1.0
> 日期：2026-11-25
> 执行时间：2026-11-25 20:00（Asia/Hong_Kong）
> 执行方式：当前会话一次性自动化启动
> 执行角色：dev1

## 1. 目标

将现有错题能力收敛到统一题库：

- 题库是唯一正式事实来源。
- “错题”是题库中的分类与快捷筛选，不再是独立数据集合。
- 现有错题录入、复习和到期提醒需求由题库查询继续满足。
- 保持现有手机、复习和兼容接口可用，不复制题目数据。

## 2. 已确认决策

1. 物理表继续保留 `mistakes`，不做表名迁移。
2. 领域对象、主 API 和页面逐步以 Question/题库为主。
3. “我的错题”作为题库内的快捷筛选保留。
4. `/api/mistakes` 保留兼容期，不立即删除。
5. 不在今晚一次性完成所有内部命名清理和物理数据库改名。

## 3. 今晚范围

### 3.1 必须完成

- 提供统一的 Question 查询入口。
- `GET /api/questions` 支持按分类筛选，默认返回全部题目。
- 错题视图通过 `category=mistake` 查询，不复制题目。
- 保留 `/api/mistakes` 兼容路径。
- 将现有错题列表的读取逻辑改为兼容适配器，底层统一走题库查询。
- 题库页面以“全部题目”为主视图，提供“错题”快捷筛选。
- 复习到期队列继续按题库中的错题分类生成，现有行为不得回退。
- 更新 OpenAPI、必要测试和兼容说明。

### 3.2 可以完成

- 将代码中的主要读取方法统一命名为 Question。
- 将页面一级入口从“我的错题”调整为“题库”。
- 在题库中保留清晰的“错题”快速入口。

### 3.3 不在今晚范围

- 不把物理表 `mistakes` 改名为 `questions`。
- 不删除 `/api/mistakes` 或现有兼容方法。
- 不重建答案、小问、掌握证据、复习计划或作答记录。
- 不修改 CI/CD、Kubernetes、OCR 服务或部署配置。
- 不实现新的题库筛选器、编辑器或全题型能力。
- 不做电子墨水屏专属功能改动；如必须修改 E-Ink 代码，停止并转交 dev-eink。
- 不合并 PR、不手工部署、不通知 QA。

## 5. 数据与兼容规则

- 现有 `mistakes` 行全部视为正式题目。
- 现有错题分类继续存放于 `question_categories`。
- 没有分类的遗留题目通过兼容逻辑视为“错题”。
- `/api/mistakes` 只能转换查询参数和响应外壳，不能维护第二份数据。
- 错题列表、复习队列和到期数量必须从同一题库事实来源计算。
- 任何写操作仍只更新原题目记录及其分类。
- 不新增会复制题干、答案或附件关联的正式题目表。

## 6. 验收标准

1. 数据库中仍只有一份正式题目事实。
2. `GET /api/questions` 默认返回全部题目。
3. `GET /api/questions?category=mistake` 返回错题。
4. `GET /api/mistakes` 的既有调用方仍能正常工作。
5. 同一道错题在题库和错题兼容视图中 ID 相同。
6. 分类、学习状态、附件、小问和答案不发生复制或丢失。
7. 到期复习数量和队列与改造前行为一致。
8. 手机题库页面能查看全部题目，并能快捷进入错题筛选。
9. 全量自动化测试通过。
10. 工作区原有未提交修改未被覆盖或提交。

## 7. 失败与停止条件

出现以下任一情况时，开发必须停止并报告，不得自行扩大范围：

- 需要重命名数据库表或重建学习数据。
- 发现复习、附件或小问数据存在无法安全映射的冲突。
- 需要修改 E-Ink 专属实现；该部分转交 dev-eink。
- 兼容接口无法在不复制数据的前提下工作。
- 23:30 前仍无法形成安全、可测试的改动。
- 全量测试出现与本次改造相关的失败且无法在计划范围内修复。
