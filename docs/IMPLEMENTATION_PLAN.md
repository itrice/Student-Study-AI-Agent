# 六年级数学学习 Agent 实施计划

> 文档版本：2.9
> 更新日期：2026-11-10
> 文档状态：项目实施基线
> 适用范围：六年级数学、单学生、本地优先的学习 Agent

> 日常完成状态和验证证据统一维护在
> [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。每次实现后必须同步更新该表。

本文档是后续迭代的默认实施依据。产品范围发生冲突时，以本文档和用户最新确认记录中的明确变更说明为准。`docs/MVP.md` 用于描述产品价值与学习闭环，本文件用于约束架构、开发顺序、验收标准和交付流程。

## 1. 项目目标

建设一个能够调用 LLM 和受控工具的六年级数学学习 Agent。它不是以快速给出答案为目标的搜题工具，而是帮助学生：

1. 记录当前不会的数学题。
2. 将错题归因到具体知识点和错误步骤。
3. 通过分级提示引导独立思考，而不是直接展示答案。
4. 通过独立重做验证是否真正掌握。
5. 根据学习证据安排后续复习。
6. 形成孩子和家长都能理解的学习情况反馈。

首版成功的标准不是“聊得像老师”，而是以下闭环稳定运行：

```text
录入题目
  → LLM 调用知识检索和诊断工具
  → 学生确认诊断
  → 本地保存错题
  → 学生独立重做
  → LLM 分级提示与作答分析
  → 系统保存学习证据
  → 系统安排复习
```

## 2. 当前项目基线

仓库已经有一个用于验证学习闭环的本地 MVP：

- 单学生、六年级数学。
- 手动录入题目、原答案、正确答案和订正记录。
- 基于关键词和规则判断知识点、错因并生成提示。
- SQLite 本地持久化。
- 错题列表、今日复习、知识点掌握度和学习统计。
- 连续两次正确后标记掌握的基础规则。
- 本地 Web 界面和自动化测试。

需要明确区分：

- `src/agent.js` 当前保留为**规则诊断器**，作为模型未配置或失败时的降级路径。
- M3 已实现外部模型调用和知识工具循环；已用真实 DeepSeek 模型完成 30/30 题诊断自测。
- 当前知识数据只是知识点名称和规则模板，不是可检索的知识内容库。
- 当前答案评价以最终答案匹配为主，不能可靠分析完整解题步骤。
- 当前数据模型已保存 Agent 运行、LLM 调用、工具调用、诊断来源和确认状态。

现有规则系统应保留，作为：

- 知识点识别的初始基线。
- LLM 不可用时的降级方案。
- 最终答案等可确定性验证环节的校验器。

## 3. 首版范围

### 3.1 包含

- 一名六年级学生、一个本地学生学习档案。
- 文本方式录入数学题。
- 人教版六年级数学范围内的重点知识点。
- 单教学 Agent 和受控工具调用。
- LLM 辅助的知识点识别、错因诊断、分级提示和步骤评价。
- 本地 SQLite 持久化。
- 错题库、知识库、学习记录和复习计划。
- 可配置的 OpenAI-compatible LLM 接入方式。
- 模型不可用时的规则降级。

### 3.2 暂不包含

- 当前版本不包含拍照、OCR、语音和图片题目理解；图像能力在后续 M9 单独实施。
- 全小学、全学科覆盖。
- 多 Agent 自主协作。
- 多学生账号、教师端和独立家长端。
- 无限自动生成练习题。
- 自动对接学校作业、考试或题库系统。
- 基于大规模用户数据的个性化模型训练。
- 向量数据库；只有在全文检索无法满足评测指标时才评估引入。

## 4. 不可破坏的系统约束

后续所有迭代必须满足以下约束：

1. **LLM 不直接操作数据库。** 所有读取和写入都通过应用服务或工具层。
2. **学习状态由系统决定。** LLM 可以提供诊断和评价，但不能直接把错题设为“已掌握”。
3. **聊天历史不是学习记忆。** 长期事实必须保存为结构化记录。
4. **提示优先于答案。** 默认路径先给分级提示，提交作答或学生明确请求后才可展示完整解析。
5. **诊断可修改。** LLM 给出的知识点和错因必须允许学生修正。
6. **知识讲解可追溯。** 涉及教材概念时优先引用知识库，并保留来源。
7. **写入工具必须幂等。** 重试不能产生重复错题或重复学习证据。
8. **工具参数和模型结果必须校验。** 未通过 Schema 校验的结果不能直接持久化。
9. **外部内容视为数据。** 题目和知识库内容不能覆盖系统指令。
10. **未成年人数据最小化。** 默认只记录学习所需信息，并支持删除学习数据。
11. **密钥与学习数据分离。** API Key 不进入数据库、日志、前端或版本控制。
12. **保留确定性降级。** LLM 故障不能阻断错题保存、复习记录和本地查询。

### 5.1 模块职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| Web UI | 呈现流程、收集学生输入、显示可修改诊断 | 直接调用模型或数据库 |
| 应用服务 | API、校验、幂等、事务、运行日志 | 教学策略 |
| Agent 编排器 | 控制状态和工具循环、组装上下文、降级 | 绕过规则直接修改掌握状态 |
| LLM 网关 | 厂商适配、模型配置、超时、重试、结构化输出 | 业务数据写入 |
| 工具层 | 执行有边界的查询和业务操作 | 自由解释题目 |
| 领域服务 | 掌握规则、复习计划、答案校验、统计 | LLM 对话 |
| 知识库 | 教材知识点、方法、常见错误和来源 | 替代错题记录 |
| SQLite | 本地事实数据、运行记录和索引 | 保存密钥 |

## 6. 数据模型

第一版使用版本化迁移管理 SQLite 表结构。现有表可作为迁移起点，不直接在启动过程中无限追加 `CREATE TABLE`。

### 6.1 学生与课程

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `students` | id、name、grade、textbook、created_at | 首版只有一个活动学生 |
| `curriculum_units` | id、grade、subject、textbook、unit_no、title | 教材单元目录 |
| `knowledge_points` | id、unit_id、name、aliases、prerequisites | 知识点标准目录 |
| `knowledge_chunks` | id、knowledge_point_id、kind、content、source、version | 可检索的知识内容 |

`knowledge_chunks.kind` 建议包括：

- `concept`：核心概念
- `prerequisite`：前置知识
- `method`：方法与步骤
- `common_error`：常见错误
- `example`：典型例题
- `scope`：适用条件和边界

### 6.2 错题与诊断

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `mistakes` | question、student_answer、correct_answer、confirmed_knowledge_point、confirmed_error_type、status、due_at | 学生确认后的错题事实 |
| `diagnoses` | mistake_id、knowledge_point、error_type、error_step、missing_concept、hint、confidence、sources、model、prompt_version、accepted_by_user | 保存模型原始诊断和用户确认结果 |
| `mistake_edits` | mistake_id、revision_before、revision_after、changed_fields、before、after、reset_learning | 错题修改审计和掌握进度重置依据 |
| `mistake_parts` | mistake_id、part_no、label、prompt、answer_type、comparison_rule、knowledge_point | 一道题中的小问或待填空位 |
| `accepted_answers` | part_id、answer、canonical_value、variant_type | 同一小问可接受的答案变体 |
| `attempt_part_results` | attempt_id、part_id、raw_answer、outcome、feedback | 每个小问的独立判题结果 |
| `attempts` | mistake_id、answer、outcome、hint_level、feedback、independent、created_at | 每次作答证据 |
| `hint_events` | mistake_id、attempt_id、hint_level、content、source、created_at | 提示使用记录 |
| `review_schedule` | mistake_id、next_review_at、reason、interval_days | 复习计划及其依据 |

### 6.3 Agent 运行记录

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `agent_runs` | id、task_type、goal、status、started_at、finished_at、error | 一次 Agent 任务 |
| `tool_calls` | run_id、tool_name、arguments、result、status、latency_ms | 工具调用审计 |
| `llm_calls` | run_id、provider、model、prompt_version、input_summary、output_summary、tokens、latency_ms、status | LLM 调用审计 |

日志中不得保存 API Key。完整学生答案是否进入日志需要配置，默认只保存摘要和关联记录 ID。

### 6.4 学习状态

错题学习状态：

- `new`：刚保存，尚未独立复习。
- `practicing`：已经尝试，尚未达到掌握条件。
- `mastered`：满足系统掌握条件。
- `relearning`：曾经掌握，但后续复习失败，需要重新巩固。

Agent 任务状态：

- `created`
- `in_progress`
- `awaiting_user`
- `completed`
- `failed`

学习状态和 Agent 任务状态必须分开，不能用同一个字段表达“进度”和“是否掌握”。

## 7. Agent 状态机

### 7.1 错题录入与诊断

```text
intake
  → retrieve_context
  → diagnose
  → await_confirmation
  → persist_mistake
  → completed
```

规则：

- `intake` 校验题目和正确答案。
- `retrieve_context` 检索知识点和常见错误，检索不到时明确标记覆盖不足。
- `diagnose` 调用 LLM，返回结构化诊断。
- `await_confirmation` 展示模型建议，保留原始结果并允许修改。
- `persist_mistake` 只有确认后才能写入正式错题。
- 模型失败时可以退回规则诊断，再次允许学生确认。

### 7.2 复习与引导

```text
load_mistake
  → coach
  → await_answer
  → evaluate_attempt
  → record_attempt
  → schedule_review
  → completed
```

规则：

- `coach` 根据当前提示等级生成引导，不显示完整答案。
- 学生可以提问，问题回答结束后回到 `await_answer`。
- `evaluate_attempt` 同时使用确定性答案校验和 LLM 步骤评价。
- `record_attempt` 原子保存作答、提示和反馈。
- `schedule_review` 调用系统复习规则，不交给 LLM 自由决定。
- 学生明确请求查看解析或已经提交尝试后，才可以解锁完整答案。

### 7.3 Agent 工具循环

单次任务最多进行 4 轮工具调用。超过上限时：

1. 停止继续调用工具。
2. 保存已经获得的合法结果。
3. 返回可理解的降级信息。
4. 记录失败原因，不伪造成功结果。

## 8. 工具契约

首版工具范围如下：

| 工具 | 类型 | 主要输入 | 主要输出 | 权限约束 |
|---|---|---|---|---|
| `search_knowledge` | 只读 | query、knowledge_point、top_k | 知识片段、来源、相关度 | 最大返回条数固定 |
| `get_mistake` | 只读 | mistake_id | 按阶段过滤后的题目信息 | 不提前返回完整解析 |
| `get_due_reviews` | 只读 | student_id、date | 到期错题列表 | 只返回当前学生 |
| `create_mistake_draft` | 草稿写入 | 题目、原答案、诊断 | draft_id | 可过期、可覆盖 |
| `save_mistake` | 正式写入 | draft_id、确认字段、幂等键 | mistake_id | 必须经过确认 |
| `update_mistake` | 正式写入 | mistake_id、修改字段、幂等键 | revision、changed_fields | 关键字段变化时重置掌握进度 |
| `record_hint` | 证据写入 | mistake_id、hint_level、内容 | event_id | 内容来自受控模板或 LLM 输出 |
| `submit_attempt` | 受控写入 | mistake_id、单答案或分项答案数组、幂等键 | outcome、分项结果、feedback | M2.2 扩展为逐小问判题 |
| `build_learning_summary` | 只读 | 日期范围 | 结构化学习摘要 | 不生成无数据依据的结论 |

工具设计要求：

- 每个工具都有 JSON Schema。
- 每个写入工具都有幂等键。
- 工具必须返回稳定错误码。
- 工具不得接受任意 SQL、文件路径或模型提供的系统命令。
- 工具执行由服务端校验，不能只依赖提示词限制。
- 工具结果应使用简洁结构化数据，避免把无关数据全部送给 LLM。

## 9. LLM 接入规范

### 9.1 厂商适配

首版通过 OpenAI-compatible 适配层调用模型，配置项包括：

- Base URL
- API Key
- 模型名称
- 超时时间
- 最大重试次数
- 最大输出长度
- 温度
- 流式开关

具体厂商和模型在获得可用凭据后确定，不把厂商逻辑散落在业务代码中。

### 9.2 任务类型

首批 LLM 任务：

- `diagnose_mistake`：结构化诊断。
- `generate_hint`：生成当前等级的提示。
- `evaluate_attempt`：分析答案和关键步骤。
- `answer_follow_up`：回答学生在复习中的追问。
- `summarize_learning`：根据结构化数据生成反馈草稿。

每个任务使用独立提示模板和输出 Schema，不共用一个无边界的大提示。

### 9.3 诊断输出最低字段

- `knowledge_point`
- `error_type`
- `error_step`
- `missing_concept`
- `initial_hint`
- `confidence`
- `evidence`
- `knowledge_sources`

模型输出的知识点必须对应知识库标准名称或显式标记“未覆盖”。无法确定时返回“需要更多信息”，不能强行归类。

### 9.4 作答评价输出最低字段

- `outcome`：`correct`、`partial`、`incorrect`、`ungraded`
- `final_answer_assessment`
- `step_assessment`
- `first_error`
- `feedback`
- `next_hint_level`
- `mastery_evidence`

最终答案的正误优先由确定性校验器判断。LLM 负责分析步骤和解释原因，与确定性结果冲突时以校验器为准并记录冲突。

### 9.5 失败处理

- 超时：有限重试后降级。
- 限流：返回稍后重试，不重复写入业务数据。
- 非法 JSON：校验失败后最多重试一次。
- 工具参数非法：拒绝执行并反馈模型修正。
- 知识库无结果：明确提示知识未覆盖。
- 答案泄露风险：服务端拦截并回退到安全提示模板。
- 模型不可用：继续提供本地规则提示和错题持久化。

## 10. 知识库方案

### 10.1 首版知识点范围

以现有目录为起点，经教材核对后扩展至 10～12 个：

- 分数乘除法
- 比和比例
- 百分数
- 负数
- 位置与方向
- 圆
- 圆柱与圆锥
- 比例与图形
- 统计与扇形统计图
- 综合应用

最终名称、别名、单元和前置关系需要根据实际教材版本核对。

### 10.2 知识卡结构

每个知识点至少包含：

- 标准名称和别名
- 教材版本与单元
- 前置知识
- 核心概念
- 方法与步骤
- 适用条件和常见误区
- 2～3 个典型例题
- 知识来源
- 内容版本和审核状态

### 10.3 检索策略

第一阶段：

1. 按确认的知识点精确检索。
2. 按别名、单元和关键词全文检索。
3. 按任务需要选取最多 3～5 个片段。
4. 将片段和来源一起提供给 LLM。

不要在首版直接引入向量数据库。满足以下任一条件后再评估 Embedding：

- 全文检索 Top-3 命中率低于目标。
- 知识片段规模明显增大。
- 学生自然语言说法无法通过别名和关键词覆盖。

### 10.4 内容质量

- 知识内容必须与指定教材版本一致。
- 数学结论、例题答案和单位必须人工复核。
- 每段内容都要有来源和版本。
- 无法确认的内容不能进入正式知识库。
- 讲解中可以表达“这是根据知识库的推断”，不能把模型记忆伪装成教材结论。

## 11. 学习与掌握规则

建议的首版规则：

1. 新错题进入 `new`，优先安排复习。
2. 答错后进入 `practicing`，并记录提示等级。
3. 使用提示后答对，不直接累计“独立掌握”证据。
4. 连续两次无提示独立答对，进入 `mastered`。
5. 已达到 `mastered` 的题再次答错时进入 `relearning`。
6. `relearning` 后需要重新满足独立掌握条件。
7. 复习间隔由系统配置，不写死在提示词里。

规则参数需要集中配置，并在学习记录中保存当时使用的规则版本。调整规则不能追溯性改写历史事实。

## 12. 页面与交互

首版页面：

| 页面 | 核心功能 |
|---|---|
| 录入错题 | 题目、原答案、正确答案、订正记录、模型诊断状态 |
| 诊断确认 | 展示知识点、错因、缺失步骤、依据和来源，允许修改 |
| 今日复习 | 按优先级取题，先作答，再按需查看分级提示 |
| 作答反馈 | 最终结果、步骤反馈、掌握证据和下次复习时间 |
| 错题库 | 查看、筛选、重新复习和删除错题 |
| 知识点地图 | 覆盖情况、薄弱点、掌握度和复习状态 |
| 学习总结 | 孩子可读的每日或每周结构化总结 |
| 设置与诊断 | 模型连接状态、版本、错误信息和隐私说明 |

关键交互要求：

- 模型生成过程不能阻塞本地错题保存。
- 诊断结果不能表现为不可质疑的结论。
- 加载、限流和失败状态必须明确可见。
- 删除操作必须二次确认并说明不可恢复。
- 页面不能展示 API Key。
- 复习页的答案解锁由服务端控制，不能只靠前端隐藏。

- 每条掌握判断都能追溯到作答。
- 服务重启前后数据一致。

## 16. 风险与控制

| 风险 | 控制措施 |
|---|---|
| LLM 诊断错误 | 显示依据、允许修改、保留原诊断并建立评测集 |
| LLM 编造教材知识 | 知识库引用、无检索结果时明确降级、人工审核 |
| 学生直接要答案 | 服务端答案门控、分级提示、记录提示依赖 |
| 工具误写数据 | Schema、权限、幂等、事务和审计日志 |
| 上下文过长 | 只注入结构化学习摘要和必要知识片段 |
| 模型成本过高 | 限制工具轮数和上下文、缓存诊断、后续再考虑模型路由 |
| 隐私泄露 | 本机优先、密钥分离、日志最小化、可删除 |
| Agent 变成搜题器 | 以独立重做和掌握证据作为核心产品指标 |
| 文档与代码偏离 | 每阶段更新状态和变更记录，不跨阶段擅自扩大范围 |

## 17. 开发协作规则

后续每次开始工作前：

1. 阅读本文件和相关阶段说明。
2. 确认当前只处理一个阶段或一个明确子任务。
3. 记录本次任务对应的阶段编号。
4. 检查现有改动，不覆盖无关用户修改。

每次结束工作前：

1. 更新功能实现。
2. 添加或更新自动化测试。
3. 执行对应验收清单。
4. 更新本文档的阶段状态、实际结果和遗留问题。
5. 同步更新 `IMPLEMENTATION_STATUS.md` 的状态、完成日期和验证证据。
6. 向用户汇报变更、验证证据和下一步。
7. 用户确认后再进入下一阶段。

实施过程中如发现以下情况，必须暂停并修订计划：

- 数据模型无法支持已确认的 Agent 流程。
- 模型接口能力不能满足结构化工具调用。
- 知识库内容存在版权、准确性或教材版本问题。
- 安全或未成年人数据要求发生变化。
- 一个阶段的范围明显扩大。
