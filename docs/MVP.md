# 六年级数学错题学习 MVP

## 用户

首发用户是一名六年级学生。直接使用者负责录入错题并完成复习；家长可以在旁观察学习记录，但不是当前版本的独立用户。

## 要解决的问题

学生会做题，但错题通常只被“看会”，没有被再次独立验证。结果是同类题仍然出错，家长只能看到分数，看不到具体薄弱点。

首版要回答三个问题：

1. 当前哪些题其实还不会？
2. 每道题应该先补哪个知识点或哪一步？
3. 怎样证明学生已经从“看懂了”变成“会做了”？

## 核心学习闭环

```text
录入错题
  → 归因到知识点
  → 先独立重做
  → 卡住时给提示，而不是直接给答案
  → 对照正确步骤订正
  → 次日再次独立重做
  → 连续答对后标记掌握
  → 7 天后回顾
```

## 首版范围

本文档描述产品目标与学习闭环。具体架构、开发顺序和阶段验收以
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) 为准。

### 包含

- 六年级数学错题手动录入。
- 允许修正录错的题目、答案、知识点和订正记录。
- 支持一道题包含多个小问或多个空格，每个小问拥有独立答案和可接受答案变体。
- 支持逐小问作答、提示、反馈和整题部分正确判断。
- 百分数、分数、比和比例、圆、圆柱与圆锥、负数、统计等知识点分类。
- LLM 辅助诊断与本地规则降级：知识点、主要错因、提示、解题步骤和常见错误。
- 单 Agent 调用受控工具，访问错题库、知识库和学习记录。
- 待复习、练习中、已掌握三种状态。
- “当前不会”和到期复习题优先。
- 独立重做与提示后重做。
- 知识点掌握度和薄弱知识点排序。

### 暂不包含

- 拍照搜题、OCR 和自动抄题。
- 无边界的大模型自由对话；模型只能在教学流程和工具权限内工作。
- 自适应生成无限练习题。
- 多学生账号、教师端和家长端。
- 自动批改完整解题过程。
- 与学校教材、作业系统或题库对接。

## 掌握规则

- 新录入：状态为“待复习”，优先进入复习。
- 第一次答错：变为“练习中”，次日再复习。
- 第一次答对：变为“练习中”，次日再独立确认一次。
- 连续第二次答对：变为“已掌握”，7 天后回顾一次。
- 中途答错会重置连续答对次数，避免把偶然记住答案当成掌握。

掌握度用于形成学习反馈，不作为学校成绩或能力标签。

## 首版验收标准

- 学生可在 2 分钟内完成一道错题的录入。
- 录入一道新题后，它立即成为下一次复习的优先项。
- 未提交答案前，复习页面不泄露正确答案。
- 学生主动请求后，才显示提示和步骤。
- 答错后可看到正确答案、订正思路和下次复习时间。
- 连续两次答对后，状态变为“已掌握”。
- 一道题包含多个小问时，只有全部小问均正确，整题才计为本次正确；连续两次全部正确后才标记掌握。
- 现有单答案错题会自动兼容为一个默认小问。
- 首页和知识点地图能正确反映错题与掌握状态。
- 关闭并重启服务后，学习记录仍然存在。

## 成功信号

首版先观察行为，而不是追求模型指标：

- 一周内是否连续录入错题。
- 待复习题是否在一周内得到处理。
- 同一知识点是否出现重复错误。
- 从首次答错到连续答对需要几次复习。
- 学生是否愿意使用提示后继续作答，而不是直接跳过。

## 迭代顺序

1. 先让真实学生连续使用 1 至 2 周，验证录入和复习闭环。
2. 增加手机拍照录题与题目校对，降低录入成本。
3. 建立受控工具层和可检索的六年级数学知识库。
4. 接入受约束的大模型诊断、分级提示与步骤评价。
5. 根据知识点和学生作答记录生成少量变式练习。
6. 增加家长周报、多学生档案和教师协作。

教育类产品必须在模型能力之前先建立可解释、可纠错和可撤回的数据边界。涉及未成年人数据时，默认最小采集、本机保存，并允许随时删除错题记录。
