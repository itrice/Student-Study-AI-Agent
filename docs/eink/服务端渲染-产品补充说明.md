## 一、结论：必须由服务端渲染

墨水屏终端是 ESP32-S3，无中文字库、RAM 只有 480KB、解码 1.87MB JPEG 要数秒。因此：

- **服务端负责排版、图片预处理、二值化，并输出 800×480 的 1bpp 原始帧。**
- **设备拿到的不是 PNG/JPEG 图片文件，而是 48000 字节的裸帧缓冲**，直接推屏。
- `/api/eink/preview` 只是给人看的 PNG，必须与设备帧使用同一份渲染结果，不能另写一套排版。
- 不新增独立 Python 渲染服务。优先在现有 Node 服务内实现；如确实无法在单容器内完成，开发者须先报产品，不得擅自增加第二个运行时。
- 不改动任何现有接口与现有页面行为。

设备是 7.5 寸、800×480；**没有电量显示区域**，页面不需要为电量预留任何矩形。

## 二、接口契约（以本节为准）

### 1）队列 `GET /api/eink/queue?limit=20`

- `limit` 取值 1~20，缺省 20；非法值返回 400，不静默截断成奇怪结果。
- `count` 是**全部到期错题数**，不是 `items.length`。
- `items` 按现有复习到期顺序返回，最多 `limit` 条；`index` 为 1 起始的本次队列序号。
- 字段：`id`、`index`、`hasPhoto`、`partCount`，`kp` 可选。
- **不得**返回题目正文、答案、提示、附件内容或附件 URL。
- 匿名只读，不加鉴权（设备无登录能力）。
- **JSON 也不能 gzip**：设备不做解压。响应不得出现 `Content-Encoding`；代理层也要确认。

### 2）整页帧 `GET /api/eink/page?id=<id>&mode=question|answer`

- `id` 必须是正整数；`mode` 缺省为 `question`，只接受 `question` / `answer`。
- 成功响应头：
  - `Content-Type: application/octet-stream`
  - `Content-Length: 48000`
  - `ETag: "<强校验值>"`（标准头，必须）
  - `X-Etag: <同一值>`（兼容设备，可选但建议保留）
  - `Cache-Control: no-transform`
  - **不得有 `Content-Encoding`**，不得 gzip、br、deflate
- 帧格式：逐行、每行 100 字节、共 480 行；MSB 在左；**0 = 黑，1 = 白**；无文件头、无行填充。
- `If-None-Match` 命中时返回 **304**，无 body，不得再带 `Content-Length: 48000`。
- `ETag` 必须随内容变化：错题、小问、附件、裁剪、排版版本任一变化都要变。
- 错误行为：
  - 非法 id / mode / limit → 400，JSON 错误体
  - 错题不存在 → 404，JSON 错误体
  - 有附件但文件丢失/损坏 → **200 回退为文字页**，并记录 warning；不得 500，也不得返回空白帧
  - 不得把错误 JSON 当成 48000 字节帧返回

### 3）预览 `GET /api/eink/preview?id=<id>&mode=question|answer`

- 返回 `image/png`，尺寸 800×480，内容与同参数设备帧逐像素一致。
- `Cache-Control: no-store`，便于改排版后手机立即看到。
- 错误行为与 page 一致。

## 三、版面裁决

7.5 寸屏为 800×480。**没有电量显示区域**。照片页按需求使用 **788×420**；这与“页脚照常”不能同时成立，因此照片页不绘制分隔线和页脚，只保留页眉。

| 区域 | 裁决 |
|---|---|
| 页眉 | y=10~56；左“错题 i/n”26px 粗体；右知识点 24px；右侧超长省略，不得压到左侧 |
| 分隔线 | 仅文字页：y=64，2px 黑 |
| 文字正文 | x=24，y=76，宽 752，高 350；28px，行高 1.55；自动降字号 28→26→24→22→20 |
| 正文字号下限 | 不低于 20px；仍放不下则在行末省略，禁止溢出到页脚、禁止半个字被裁 |
| 文字页页脚 | y=436~480；18px 按键提示；不预留电量区 |
| 照片题 | **x=6~794，y=56~476，恰好 788×420**；等比缩放、居中、白底留边；不排正文，不画分隔线，不画页脚 |
| 照片页页眉 | 保留 y=10~56 的“错题 i/n”和知识点 |

说明：

- 照片页底部到 y=476，剩 4px 白边；任何内容不得越过 y=476。
- 如果照片原图比例不是 788:420，按比例缩放后居中，四周用白色填充，不得拉伸变形。
- 若后续产品要求照片页也显示按键提示，必须把照片高度降到 376 或更小；788×420 与页脚不可同时保留。
- 参考实现 `docs/eink/eink_ref_server.py` 如存在，只作为算法参考；输出必须符合本文件，不能因为参考实现有不同的页脚/尺寸就照抄。

### 文字页内容

- `question`：题干 + 所有小问题干。**不得**出现正确答案、解析、错因、提示、学生答案。
- `answer`：按小问分组显示“你的答案 / 正确答案 / 错因或解析 / 知识点”。多小问顺序排列，不得串行、重叠、溢出。
- 照片题的 `answer` 仍为文字页，不重复贴整页照片。

### 照片处理（顺序不可变）

1. `exif_transpose` 按 EXIF Orientation 旋转。
2. 按“白纸亮区”裁掉桌面和页边阴影：缩到 120×90，亮度 ≥195 的像素求包围盒；包围盒小于 55% 时退回“墨迹包围盒”。
3. 边缘垫 6~10px 白，避免局部均值在边界拉出黑框。
4. 局部自适应阈值：`BoxBlur(11)` 求局部均值，像素 < 均值减 8~12 判黑，其余判白。
5. 若已有前端 `crop`，优先用 crop 结果，再执行第 3、4 步。
6. **禁止 Bayer 抖动、禁止全局阈值**。原片偏暗（灰度均值约 143），抖动会成一团灰。

## 四、性能、缓存与实现约束

- 单页热缓存响应目标 <300ms；冷渲染 <1.5s；设备超时 10s。
- 内存 LRU 缓存帧，key 至少包含 `id + mode + 内容修订号 + 排版版本`；建议容量 ≤32 页。
- preview 复用同一缓存帧，不重复渲染。
- 中文字体必须随镜像打包（建议 Noto Sans SC，OFL 许可，保留许可证文件）；容器内不得依赖系统字体。
- 不得运行时联网下载字体或模型。
- 新增图像依赖如必须联网安装，开发者先报告版本、许可、镜像体积和 alpine/musl 兼容性，得到确认后再装。
- 只读接口不得写数据库、不得触发复习记录、不得改变错题状态。

---

## 五、安全与验收环境

- 接口匿名只读是产品接受的现状，但仅限家庭局域网；不做 CORS，不加 `Access-Control-Allow-Origin: *`。
- 响应加 `X-Content-Type-Options: nosniff`。
- 日志只记录 `id/mode/status/耗时/是否命中缓存`，不记录题目正文、答案或图片内容。
- 开发与验收一律使用隔离数据库和独立端口；**不得连接或写入 `192.168.1.66:3000` 正式实例**。
- 允许把正式库与附件目录**只读复制**到临时目录，用于真实照片的视觉验收；不得反向写回。

## 六、验收基线（验收者按此逐项给证据）

### 硬格式

1. `curl -s .../api/eink/page?id=<id>&mode=question -o frame.bin` 后文件长度恰为 **48000**。
2. 响应无 `Content-Encoding`；`Content-Type: application/octet-stream`；`Content-Length: 48000`。
3. 解码脚本按“每行 100 字节、MSB 在左、0=黑”还原 PNG，画面方向正确；把 0/1 反过来应明显花屏，证明方向未写反。
4. `ETag` 存在且为强校验值；带 `If-None-Match` 第二次请求返回 304 且无 body。
5. 修改该题答案或裁剪后，`ETag` 必须变化，帧内容随之变化。

### 画面

6. 纯文字题：28px 起排，长题自动降字号，最低 20px；不溢出、不压页脚、不出现半个字。
7. 多小问：题干与答案均按小问分组，顺序正确，不串行。
8. 照片题：**照片区恰好 788×420（x=6~794，y=56~476）**，整页大图，非 340px 小框；中文可辨认。
9. 照片页不得出现分隔线、页脚或电量预留区；页眉“错题 i/n”和知识点仍可见；照片下边缘不得越过 y=476。
10. 照片方向正确（EXIF 旋转生效）；无明显桌面阴影；无四边黑框；无整团灰。
11. `question` 模式不得泄露正确答案/解析/错因/提示/学生答案；`answer` 模式内容完整。
12. 附件缺失时回退文字页，仍为 48000 字节且可读。
13. 非法 id、非法 mode、非法 limit 返回 400/404 JSON，不得返回伪帧。

### 一致性与兼容

14. `preview` 与同参数 `page` 解码结果逐像素一致（允许 PNG 元数据差异，不允许画面差异）。
15. 队列 `count` 等于全部到期数；`limit=1/20` 边界正确；`index` 连续；不泄露正文。
16. `/api/review/*`、`/api/mistakes/*`、附件端点回归通过，现有手机页面无变化。
17. 容器从零构建成功；容器内中文正常，无 tofu；冷启动后首帧可出。
18. 串行请求 20 页无 429、无超时；如出现 429，停止并报告，不得据此判通过。

### 视觉抽查

19. 至少覆盖：纯文字、长文字、多小问、照片题、照片+多小问、附件缺失、无到期题空队列。
20. 每类至少 1 张 preview 截图存档；照片题必须人工确认“能读”，不能只看字节数。
